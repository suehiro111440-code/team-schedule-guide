「次の会議はいつ？」「この仕事は誰が担当？」
その確認を減らすために。SlackとGoogleを使って、連絡から実行までの流れを整えます。

10人ほどのチーム向け既存のGoogleアカウントを活用まず2週間の試行

連絡する

予定を見る

日程を決めるときは「調整さん」で回答を集めます。

導入のポイントは、「置き場所」と「更新する人」をセットで決めること。
会話はSlackにまとめ、決まった予定と締切をそれぞれの管理場所に残します。

01

4つの道具を、役割で使い分ける。

すべてを毎回開く必要はありません。「いま何をしたいか」で使う場所が決まります。

#

Slack

連絡・相談の入口

会議や依頼ごとに投稿。その下の「スレッド」に、関連する会話をまとめます。

○

調整さん

候補日の回答を集める

参加できる日を○・△・×で回答。共有URLをSlackに貼って案内します。

日

Googleカレンダー

確定した会議を見る

日時、参加者、場所、オンライン会議のURLを登録。最新の予定を共有します。

✓

スプレッドシート

担当・締切・進捗を見る

仕事を1件1行で管理。「未着手・進行中・確認待ち・完了」を一覧で確認します。

確認先のルール：会議の日時はカレンダー、仕事の締切と進捗は一覧表。Slackには、それぞれへのリンクを置きます。
02

会議は「回答を集める → 確定して共有」。

会議の主催者が、調整から予定の更新まで担当します。

  1. STEP 1 / SLACK

    調整を案内

    目的・参加者・所要時間・回答期限と、調整さんのURLを投稿。

    主催者
  2. STEP 2 / 調整さん

    都合を回答

    候補日に○・△・×を入力。相談や補足はSlackの同じスレッドへ。

    参加者
  3. STEP 3 / カレンダー

    日時を確定

    主催者が日時を決め、カレンダーに登録して参加者を招待。

    主催者
  4. STEP 4 / SLACK

    確定を知らせる

    確定日時と予定のリンクを投稿。対象者にメンションし、確認を受ける。

    主催者 → 参加者

SLACKの投稿イメージ（架空の例）

次回打ち合わせの日程調整参加者：関係メンバー
目的：今月の進捗確認／30分
回答期限：○月○日 17:00
調整さん：［出欠表のURL］
↳ 候補日の相談・補足は、このスレッドに。

予定が変わったら

① カレンダーを更新
② Slackで対象者に知らせる
③ 確認のリアクションをもらう

カレンダーの更新は主催者が担当。定例会議は曜日・時間を固定できると、毎回の調整を減らせます。

調整さんのURL共有と、確定後のカレンダー登録は人が行う運用案です。この図は自動同期を表すものではありません。

03

仕事は「1件1行」で、担当と締切を見える形に。

依頼する人が担当と締切を明記し、担当者が進捗を更新します。

  1. STEP 1 / 一覧表

    仕事を登録

    仕事・担当者・締切日時・成果物の保存先を記入。

    依頼者
  2. STEP 2 / SLACK

    担当者に依頼

    担当者にメンションして一覧表を案内。担当者は引き受けを返信。

    依頼者 → 担当者
  3. STEP 3 / 一覧表

    進捗を更新

    着手・確認待ちの状態を更新。遅れそうなら、期限前に相談。

    担当者
  4. STEP 4 / 一覧表・SLACK

    完了を記録

    必要な確認を受けて一覧表を完了にし、スレッドで成果物を報告。

    担当者・依頼者

締切一覧のイメージ（架空の例・横にスクロールできます）

仕事担当者締切日時状態関連資料
会議資料の作成担当A○月○日 17:00進行中資料のリンク
提案内容の確認担当B○月○日 12:00確認待ち提案書のリンク
議事メモの共有担当C○月○日 18:00完了議事メモのリンク
締切を変えるとき：担当者と依頼者が相談して、新しい期限を決定 → 一覧表を更新 → 同じSlackスレッドで共有。未確定の日付は「仮」と記します。

仕事の締切は一覧表に集約。最初からすべてをカレンダーにも転記すると、変更時の更新箇所が増えてしまいます。

04

Slackは、少ない部屋と共通ルールで始める。

会話をまとめる工夫と、通知を確かめる習慣を組み合わせます。

最初のチャンネルは3つ

  • # 全体連絡全員への周知、運用ルール、カレンダーと一覧表のリンク。
  • # 会議・日程調整会議ごとに投稿。回答の案内、確定、変更をまとめます。
  • # 仕事・締切確認依頼ごとに投稿。相談、進捗、完了報告をまとめます。

全員でそろえる4つの行動

  1. 返信は同じスレッドへ。
    関連する話を一つの場所にまとめる。
  2. 依頼には担当と期限を。
    受けた人は引き受けを返信する。
  3. 確定・変更は対象者にメンション。
    確認したらリアクションする。
  4. 毎営業日、予定と締切を見る。
    運用担当は週1回、未完了の仕事を確認する。

最初に使う連携

Googleカレンダー → Slack
公式アプリを導入し、各メンバーが自分のアカウントを接続。会議前の通知を受け取ります。

Slackの定期リマインダー
「毎週、締切一覧を確認する」通知を設定し、確認の習慣を作ります。

チーム内の担当を決める

主担当1人 ＋ 代わりの担当1人
メンバーの追加、リンクの整備、週1回の確認を担当します。

LINEからの切り替え日を決める
試行対象の業務連絡はSlackへ。緊急連絡をLINEや電話で受けた場合も、決定した内容を管理場所に反映します。

個別の締切を一覧表から自動通知する仕組みや、チャンネルへの予定自動投稿は初期導入に含めず、試行後に必要性を判断します。

05

一つの会議・一つの案件で、2週間試す。

全員が迷わず使えるかを確かめながら、チームに合う運用に整えます。

導入前 / 準備

使う場所を整える

アカウント・共有権限を確認。Slackの部屋、共有カレンダー、締切一覧、投稿のひな形を用意します。

1〜2週目 / 試行

実際の業務で使う

対象の会議と案件で運用。説明を受けたメンバーが登録・回答・更新を行い、困った点を集めます。

2週間後 / 見直し

続けやすく直す

通知の量、更新忘れ、スマホの使いやすさを確認。ルールを修正し、継続・展開の範囲を決めます。

試行前と試行後に、同じ3点を確認します。

調整の手間会議日時が決まるまでのやり取りは減ったか。

予定の見落とし確定・変更の連絡が、対象者に届いたか。

締切前の確認担当不明や、期限を過ぎてから気づく仕事は減ったか。

設定から、使い方の定着まで。

AI伴走者が、初期設定・投稿のひな形・締切一覧・1枚の運用ルール・操作説明・試行後の見直しを支援する案です。開始日、運用担当、対象の会議・案件を打ち合わせで決めていきます。

06

導入前に、確認しておきたいこと。

このページは導入案です。実際のSlackやGoogle環境の設定・連携は、これから行います。

Slack無料版の履歴は、どう扱いますか？

閲覧・検索できるのは直近90日分です。1年を超えるメッセージやファイルは削除されます。保存設定によって90日で削除することもできます。長く必要な予定、締切、決定事項、成果物はGoogle側に残します。スレッドやピン留めだけでは長期保存になりません。

「調整さん」とSlackは自動でつながりますか？

今回の案では、調整さんのURLをSlackに貼って案内します。日程の決定とカレンダーへの登録も主催者が行います。特別な自動連携を作らずに始められる構成です。

費用や、Googleアカウントの準備は？

まずは既存アカウントと各サービスの無料で利用できる範囲を確認して構成します。Google Workspaceの契約有無、管理者による制限、共有権限は導入前に確認します。有料プランが必要な場合の利用料と導入支援費は、対象範囲を決めてからご案内します。
